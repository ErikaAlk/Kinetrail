# 秤是怎么算出那几十项的

WLA37（沃莱 P3 用的算法）的工作原理。协议、逆向过程和移植记录在 `P3.md`，
可运行的实现在 `p3/wla37.py`。

**本文所有数值都是合成示例**（70 kg / 175 cm / 30 岁 / 男 / 普通体型，配合成阻抗），
不是真人读数。想复现直接跑 `p3/wla37.py`。

## 秤真正测到的只有两样

**体重**和**十个阻抗值**。其余全部是算出来的。

八电极 = 四个脚电极 + 手柄上四个手电极。电流从一侧注入、另一侧测电压，分别拿到躯干、
左臂、右臂、左腿、右腿五段的阻抗；双频再乘二，正好十个。

怎么判断哪个下标是哪一段？回归式里有这一项：

```
z0 + (z1·z2)/(z1+z2) + (z3·z4)/(z3+z4)
```

`(z1·z2)/(z1+z2)` 是**并联电阻**公式。两条手臂并联、两条腿并联、再和躯干串联——这就是
全身阻抗的电路模型。所以 `z0` 是躯干（实测二三十欧，远小于四肢的两三百欧，因为躯干短而
粗），`z1/z2` 是两臂，`z3/z4` 是两腿，`z5..z9` 是同样五段的第二个频率。

这也解释了为什么 `decode.py` 里阻抗要按「小、大、大、大、大」重复两遍来理解。

## 阻抗为什么能推体脂

瘦体组织含水和电解质，导电；脂肪基本绝缘。所以阻抗越高，脂肪比例越高。经典 BIA 指标是
`身高² / 阻抗`，正比于去脂体重。

**双频是关键。** 低频电流过不了细胞膜，只走细胞外液；高频能穿进细胞，反映全身水。两个
频率的差就携带了细胞内外水分布的信息。所以回归式里有整整五项 `z[i] - z[i+5]` 和五项
`z[i] / z[i+5]`，都是在榨这个频率差。

## 体脂：27 项线性回归，分三档

`calcBF` 的输入项：

| 类别 | 项 |
| --- | --- |
| 体型 | 体重、体重²、身高²、身高、BMI |
| 频率差 | 五段各一项 `z[i] - z[i+5]` |
| 全身阻抗 | 两个频率各一项并联组合 `/ 身高²` |
| 频率比 | 五段各一项 `z[i] / z[i+5]` |
| 交叉项 | 八项 `阻抗 × BMI` |
| 汇总 | `(前五之和/身高)/身高`、`(后五之和)/身高²` |

乘上 27 个系数加截距，输出的是**脂肪质量 kg**，不是百分比。

**分三档**：按 `(前五个阻抗之和 / 身高)` 卡在 9 和 12 两个阈值上，三档各有一套完全不同的
系数。这是用分段线性去凑非线性——单一线性模型盖不住整个人群。

三张表里都有五个系数恰好是 0（第 14、15、16、19、22 项），厂商拟合时把这几项剔掉了，
但表的形状留着。

**注意：`calcBF` 不用年龄，也不用性别。** 体脂率只由体重、身高和十个阻抗决定。年龄和性别
只在后面影响参考值、体型评分和代谢年龄，不进体脂本身。

算完除以体重变百分比，夹在 [3%, 60%]，四舍五入到一位小数。

## 之后就不再用阻抗了

从体脂率往后全是固定比例分解，一个阻抗都不碰：

```
去脂体重 = 体重 - 脂肪
  ├─ 水      = 去脂 × 0.733
  ├─ 蛋白质  = 去脂 × 0.2
  └─ 骨      = 去脂 × 0.067          （三项加起来正好 1.0）

肌肉     = 水 + 蛋白质 = 去脂 × 0.933
骨骼肌%  = (水kg × 0.834 - 2.627) / 体重 × 100
基础代谢 = int(去脂 × 21.6 + 370)
皮下脂肪 = (体脂率 × -0.0002 + 0.72) × 体脂率        ← 只是体脂率的二次曲线
内脏脂肪 = int(脂肪kg × 0.502 - 去脂 × 0.029 - 0.477)，夹在 [1, 20]
代谢年龄 = 实际年龄 + 按体脂率分桶的偏移（男 <14% 减 3，≥36% 加 5）
体型评分 = 80 + 相对标准去脂/标准脂肪的残差修正
标准 BMI = 成年男 22 / 女 21（常数，与身高无关）
```

合成示例（70 kg / 175 cm）算出体脂率 17.4%，去脂 57.8 kg，然后：

| 指标 | 算法输出 | 手算核对 |
| --- | --- | --- |
| 基础代谢 | 1618 | `int(57.8 × 21.6 + 370)` = 1618 |
| 身体水 | 60.5% | `57.8 × 0.733 / 70 × 100` = 60.52 |
| 蛋白质 | 16.5% | `57.8 × 0.2 / 70 × 100` = 16.51 |
| 骨重量 | 3.9 kg | `57.8 × 0.067` = 3.873 |

**所以几十项指标里，真正独立的信息只有两个：体重，和阻抗推出来的体脂率。** 其余都是这
两个数的代数变换，显示到 0.1 的精度远超实际信息量。

## 那些超过 100% 的分段数值

App 报告里躯干可能显示 156%、下肢 130%，看着很怪。代码里是这样的：

```
躯干脂肪显示值 = 躯干脂肪kg / (身高×0.006 + 标准脂肪量×0.389 - 0.683) × 100
```

分母是按身高和标准体脂算出的**该部位参考值**。所以那不是「躯干脂肪占比」，而是**相对同类
人群标准的百分比**——156% 意思是躯干脂肪是参考值的 1.56 倍。App 上写的「标准范围
80%–160%」就是这个意思。

各段的脂肪和肌肉质量本身是各自的三项小回归，例如手臂脂肪：

```
z6 × 0.007476 + 脂肪kg × 0.081201 - z1 × 0.005752 - 0.662152
```

## 三个能看出「这是产品不是论文」的地方

**左右强行拉平。** 如果算出来左右臂差超过 0.3 kg（腿是 0.5 kg），代码直接把差的那侧拽回来，
补偿量是 `(两个阻抗之和) / 20213`。这个 20213 没有物理意义，是调出来的魔数。所以看到的左右
差异有一部分是被「修」过的。

**到处是下限兜底。** 手臂脂肪低于 0.1 kg、肌肉低于 0.2 kg 就强行抬上去，防止出现负数或零。

**自己手写的四舍五入。** 设备全程用 float32 算，而且不用标准库取整，是一段手写的 `fmodf`
逻辑，还专门处理 `x.99xxx` 的进位。移植时必须把 float32 精度也复刻出来，否则末位对不上，
这就是 `wla37.py` 里 `f32()` 到处套的原因。

## 对 Kinetrail 的意义

网关存**体重 + 10 个原始阻抗**，比存几十项输出信息量更大：那些输出随时能重算，反过来不行。
哪天想换算法（用公开的 Kyle、Janssen 公式重算，或自己拟合），原始阻抗还在，历史不用重测。

反过来，从 Health Connect 拿到的那几项（体重、体脂率、水分质量、骨量、基础代谢、去脂体重）
**不是彼此独立的证据**——后四项都是前两项的固定比例变换。据此做趋势解读时要当心，
比如「骨量上升」和「去脂体重上升」说的是同一件事。
